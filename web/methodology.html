How Psychometric-Pulse thinks

A short weekly check-in, a fair comparison, and a model that rebuilds itself from each school's own data. Play with the demos below, which run the real detection engine.

Notice early. Support early.

The idea in 30 seconds

🕑

Ask more often, ask less

A 5-question weekly pulse replaces a long yearly test. Small changes show up while there is still time to help.

⚖️

Compare fairly

If a respected teacher leaves, a whole class dips. The model removes that shared movement so it only flags what is different about the student.

🤝

Support, never label

An alert is a prompt for a private conversation with a counsellor. It is never a diagnosis and never goes to parents automatically.

From pulse check to alert

1

Collect

One row per student per week: pulse score (1-10), attendance %, late submissions, plus school-level notes such as exam weeks and teacher transfers. IDs are anonymous.

2

Remove the environment

For every class and week, take the median score and subtract how far it sits from that class's usual level. What is left is the student's adjusted score. Small classes fall back to the whole-school effect.

adjusted = score − (class-week median − class overall median)
3

Look for signals

Low: adjusted score below the floor (5.0; 5.5 in early mode). Decline: three screenings in a row going down, smoothed, by at least the trend threshold. Sharp drop: far below the student's own first three weeks.

4

Grade the alert

Signals are combined with attendance and late work, so one bad day never triggers a red flag.

Greenno signal
Yellowmild one-step drop
Orangea signal fires
Redsignal + attendance / late work
5

Rebuild

Every upload re-estimates the thresholds from that school's data, in memory, then forgets the data. See "A model that rebuilds itself" below.

A model that rebuilds itself

Each school is different: some pulse scores are noisy, some schools score lower on average. A fixed rule would over-alert in a noisy school and under-alert in a calm one. So on every upload the model re-estimates its thresholds from that school's data alone.

What is learned

  • Noise: robust spread of week-to-week change in adjusted score. Sets the decline and sharp-drop thresholds, scaling with noise (3.55 x noise and 4.45 x noise).
  • Attendance norm: the school's own typical attendance sets what "low" means.
  • Early mode: with 8 or fewer screenings per student the model needs a smaller fall to alert (0.8 / 1.2 points instead of 1.6 / 2.0) and uses a 5.5 floor, because a short history leaves less time to wait.
  • Not learned: the low-score floor (5.0, or 5.5 in early mode). It stays absolute so a school with generally low scores is not taught to ignore them. Tested: learning it cost about 15 points of early detection.
rebuilt = w × learned + (1 − w) × default
w = rows / (rows + 500)

Privacy by design: rebuild, don't store

The model is a handful of numbers recomputed from the file you upload. The file is parsed in the browser tab, held in memory, and gone when you close the tab or press Forget all data. The code uses no cookies, no browser storage and makes no network requests with your data, and an automated test fails the build if that ever changes. Because nothing persists, a school that wants to keep improving the model simply uploads its files again, or several at once.

How much data does a teacher need?

Minimum: 3 screenings

Enough to draw a trend line and a rough forecast. At 3 screenings about half of the flags are false alarms and few real declines are visible yet, so treat alerts as "keep watching", not as findings.

Recommended: 5 screenings, 10+ students

Five weekly scores per student in one class of ten or more gives usable alerts and forecasts: in simulation roughly 7 in 10 or more flagged students were genuinely declining, with about 4 in 100 healthy students flagged.

Reliable: 8+ screenings

From eight screenings the model catches roughly four in five declining students with few false alarms, and keeps improving to 12.

What the simulation says

One class, about 20% of students starting a decline at some point. Measured at the latest week, which is what the teacher sees. Early mode (8 or fewer screenings per student) is applied automatically.

Reading the forecast plot

For each student the dashboard draws a straight line through their last 6 adjusted scores and extends it 4 weeks. The shaded band is an approximate 80% range. It is deliberately never narrower than the school's normal week-to-week noise, so three lucky points cannot look certain.

  • Outlook "floor in ~N wk": the line is falling and would cross the 5.0 floor in about N weeks if nothing changes.
  • Accuracy: in simulation the band contains the actual score about three times in four (a little under its 80% promise), and the 3-week-ahead error is typically 0.6 to 0.9 points once there are 5 or more screenings (about 1.2 with only 3).
  • A forecast is not a diagnosis: real students change course when someone helps. A forecast is a reason to check in, and a good outcome is one where the forecast turns out wrong.

Limits we state openly

Synthetic data

Thresholds were tuned on the same simulator that produced the evidence. The numbers prove the mechanism, not real-world accuracy. A pilot on anonymised real data is the next step.

Trade-offs

Earlier warning means more false alarms. The rebuild reduces them modestly (about 17% to 14%) and gives up roughly 0.1 weeks of lead time. Counsellor judgement stays in charge.

Reference level

Adjusted scores are measured against each class's typical level over the period uploaded. A long class-wide dip therefore pulls that class's adjusted scores down by up to about a point. A longer history or a logged baseline period would fix this.

Fairness

Before scaling, alert rates must be audited by gender, socioeconomic status, language and disability, and scores compared with counsellor assessments.

Roadmap

12-week pilot in one school → compare alerts with counsellor judgement → tune → difference-in-differences for teacher transfers → fairness report → expand to 3-5 schools.
